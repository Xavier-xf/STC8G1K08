## 日志字段解释

- START从停止状态进入startup并重置本轮心跳，立即 `heartbeat_seen=0` 正常；已启用时重复START不重置运行状态。
- STOP只停外部复位监测，仍统计正常心跳，所以stopped时edges继续增也正常。
- `heartbeat_seen=1` 表示此前见过心跳，不是实时健康证明。超时日志仍seen=1正常。
- 前一下降沿由后一下降沿确认，正常age_ms可能约200至400 ms；它不是物理线上最后一个下降沿的直接年龄。
- 单线请求/应答期间暂停普通心跳，协议边沿不用于保活。因此连续READ期间edges短时不变、age_ms约1至2秒后恢复正常；本次CLI全部确认成功，没有5秒误复位。
- 串口拆包可能把一行分为多个“接收”条目；不把拆行看成STC重启。
- 暂停整个应用会暂停串口和视频线程，恢复后串口epoll或视频等待超时与试验条件相符，不直接归因于开漏。此处没有展开或修改其他业务模块。

## v1.2.0 接收方复测方法

先在Keil Rebuild记录零错误/零警告、DATA/XDATA/CODE、M51、HEX SHA-256及源版本。旧基线112/0/4283不能填成本版结果。容量不足或出现overlay警告时先保留完整输出，不改XDATA来绕过。

### 1. 基础通信及STOP

烧录本版新HEX，主机暂用原已验证程序。横幅应为v1.2.0及 `recovery=120000ms`。在允许复位的测试板上：

```sh
/home/application/cpu_check_ctl read
sleep 1
/home/application/cpu_check_ctl stop
sleep 1
/home/application/cpu_check_ctl read
sleep 1
/home/application/cpu_check_ctl start
```

READ/STOP/START应CONFIRMED，STOP为enabled=0/phase=0，随后START为enabled=1/phase=1/heartbeat_seen=0。等待35秒后READ应phase=2；再次START不退回宽限。100次基础READ按原实板步骤执行，不用自动重试隐去失败。STOP确认后暂停应用至少8秒并恢复，不应主机复位；检查boot_id或uptime，PID以当前`ps`结果为准。

### 2. 正常复位与恢复

START确认、越过宽限并确认phase=2，然后停止普通心跳（在测试板暂停整个应用）。观察最后有效心跳后约5秒触发P5.5、主机真正BOOT0/U-Boot/kernel重启。主机自启恢复心跳后应回monitoring，记录从释放到恢复的最坏时间；正常恢复早于120秒则不出现第二个脉冲。串口日志不能代替示波器脉宽。

### 3. 主机一直起不来时的重复复位

1. **事先通过当前板子的维护机制临时停用应用开机自启，并记录如何恢复**；不要删除可执行文件或修改SDK。保持现有应用运行，通过CLI确认START并越过宽限。
2. 停止当前应用心跳，允许第一个真实复位发生。由于已停自启，主机重启后不会恢复应用心跳；不要这时发STOP。
3. 连续记录至少3个P5.5脉冲：首次约5秒无心跳后发生，之后各自从前一次释放起等约120秒再断言，reset计数逐次增长。主机尚未重发START也应继续复位；STC不应重新出现冷启动横幅。
4. 在下一恢复窗口内通过维护机制启动应用，心跳恢复后应结束重复复位并进入monitoring；恢复应用开机自启配置。
5. 测试异常时可用已确认STOP停止外部监测，或让STC真正冷上电回stopped。**仅重启主机不能退出已启用STC的重复复位**。事先准备好可用电源/维护方式，只在测试板进行。

### 4. 高负载与电气

视频预览/通话/刷卡等真实业务并行时做1000次READ，每次间隔1秒，记录成功/失败总数及第一次失败的tx_late/rx_edges/rx_bits/bad_frames/clock_changed，不靠重试算通过。示波器看PH15/P5.4两端高低电平、释放上升沿、4 ms STC应答低脉冲及8/14 ms位间隔，另测P5.5复位脉宽。4 ms只改善采集余量，不能消除中断线程调度及时间戳误差。

32位49.7天回绕和16位链路回绕有主机模拟覆盖，量产仍须长稳测试。内部WDT、POR/LVD、丢STOP应答和业务线程单独卡死检测是独立验收项，不用`kill -STOP`测试替代全部场景。
