# STC8G1K08 看门狗固件

独立的 STC8G1K08 外部看门狗固件。当前源码版本为 `1.2.0`，版本定义位于 `User/Config.h`。仅支持一种单线短帧协议：3 字节请求、5 字节应答。

复制整个 `firmware/` 即可取得全部工程源码、寄存器定义、测试及说明，不引用父目录、Linux 源码、Shared 副本或同步脚本。接收方另行准备 Keil C51、适配的 STC 器件环境和 STC-ISP。Linux 端单独交付 `stc_watchdog/`；本产品的 `cpu_check/`、socket、CLI、UI 与升级业务不是固件依赖。

**本版已修改生产源码，接收方须Rebuild并烧录同次HEX。用户本次Keil为data=105.0/xdata=0/code=4433，零错误零警告，基础实板通过；重复复位、电气、高负载及栈审查仍未验收，不能直接量产冻结。**

Keil 只编译五个正式 C 文件：

| 文件 | 职责 |
|---|---|
| `User/main.c` | 板级初始化、中断入口、原子心跳快照、命令执行及复位输出编排 |
| `Driver/src/heartbeat_monitor.c` | 心跳记录与宽限/超时判断，不直接访问寄存器 |
| `Driver/src/reset_controller.c` | 复位脉冲及恢复窗口状态机，不直接访问寄存器 |
| `Driver/src/cpu_check_link.c` | P5.4 单线收发、CRC、有限帧交接及协议边沿分类 |
| `Driver/src/uart.c` | TX-only 串口诊断 |

`Driver/inc/stc8g1k08_regs.h` 是本工程所需的最小寄存器定义。纯逻辑模块保留在现有 Driver 目录，以接口区分职责，不为小型固件增加目录层次。原 `maintenance_runtime` 已整体更名为 `cpu_check_link`，正式工程和测试均引用新名称；没有旧接口兼容层。

## 运行契约

- P5.4：CPU_CHECK 通信与心跳，由 `cpu_check_link` 独占模式与输出；低电平主动下拉，高电平高阻释放，必须有兼容双方电压的外部上拉。Linux 配套模块也使用开漏输出。
- P5.5：独立推挽复位输出，正常/停止/宽限/恢复均为低，复位为高。运行中只经 `apply_reset_output` 操作，模式仅初始化一次。脉冲配置为200 ms，由主循环释放，实际时长包含主循环响应延迟，须实测。
- 冷上电及低压复位默认停止外部监测，以便烧录和调试；主机未发START时，不会靠外部看门狗恢复主机。仅内部WDT复位且没有POR/LVD标志时自动恢复监测。
- 从停止状态START：启用、清空本轮心跳、开始30秒宽限。已启用时重复START不重置宽限、心跳、复位状态或恢复窗口。宽限只用于STARTUP，避免32位起始年龄回绕后重新宽限。
- 越过宽限后，无有效心跳达到5秒时断言复位；脉冲结束进入WAIT_RECOVERY，给主机完整120秒恢复窗口。窗口内心跳恢复则回到MONITORING；仍未恢复则再发复位脉冲，持续重复，无次数上限。正常未恢复时，相邻脉冲起点约间隔120.2秒，含主循环延迟。
- 120秒是配置值，不是对任何主机都安全的常数。现有日志从复位到心跳恢复约43秒；量产镜像须多次测量，配置不应小于最坏实测值的2倍。恢复窗口太短会打断正常开机。
- STOP停用外部监测，立即释放正在进行的复位并终止后续重复复位；仍接收心跳，STC内部WDT不停止。停止后无需续租。随后START重新开始宽限。
- READ不改状态、不刷新保活、不延长宽限或恢复窗口。查询和STC自身应答不能充当普通心跳。
- `heartbeat_seen` 表示本轮见过有效心跳，不是此刻健康证明；应结合phase和主机缓存有效性理解。
- 主机初始化心跳不等于启用监测，须提交START并检查确认；退出/升级前必须确认STOP。无应答不能推断命令未执行。

## 唯一短帧协议

### 这是什么协议

这是本模块自定义的**单线、半双工、开漏、下降沿间隔编码协议**，不是UART、I²C、SPI，也不是Dallas/Maxim标准1-Wire。CPU_CHECK一根线同时承载普通心跳、主机请求和STC应答；没有独立时钟线，由相邻下降沿的时间差表示位0/1。高电平表示双方释放，靠外部上拉形成；低电平表示当前发送方拉低。

主机主动发命令，STC只在收到有效请求并由主循环执行后应答；任何时刻只有一方发送。P5.5/AP_RESET是独立的复位控制线，不承载协议数据。没有设备地址、UART起止位、帧长度字段、会话或自动重试，固定长度与前导用于帧同步。

### 帧与状态

各字节最高位先发，字段顺序如下：

| 方向 | 字节0 | 字节1 | 字节2 | 字节3 | 字节4 |
|---|---|---|---|---|---|
| 请求 | 命令 | 非零序号 | CRC | — | — |
| 应答 | 命令 OR 0x80 | 原序号 | 结果 | 状态 | CRC |

START=1、STOP=2、READ=3；执行结果成功0、无效命令1。CRC-8：poly=0x07、init=0、不反射、末尾不异或，覆盖CRC前所有字节。CRC错误、半帧、零命令、带应答位的请求或零序号不执行。有效未知命令返回无效命令结果。

状态bit0=启用，bit1=见过心跳，bit2..4=阶段，bit5..7=0。阶段：停止0、启动宽限1、监测2、复位3、等待恢复4。计算为 `status = enabled | (heartbeat_seen << 1) | (phase << 2)`。状态在命令执行后准备应答时取样，不是收到应答时的实时状态。固件版本、心跳年龄、复位次数只从串口观察，不占帧字节。

以下是计算示例，所有数值均为十六进制；具体状态随设备实际阶段变化，不是固定响应。CRC允许等于00，只有序号要求非零：

| 操作 | 主机请求 | STC应答示例 | 应答含义 |
|---|---|---|---|
| START，序号07 | `01 07 00` | `81 07 00 05 2A` | 执行成功，enabled=1、phase=1、heartbeat_seen=0 |
| READ，序号08 | `03 08 07` | `83 08 00 0B 6B` | 执行成功，enabled=1、phase=2、heartbeat_seen=1 |
| STOP，序号09 | `02 09 15` | `82 09 00 02 29` | 执行成功，enabled=0、phase=0；此前见过心跳 |

主机必须核对响应命令、原序号、CRC、执行结果及合法状态。收到完整请求、调用API返回受理，或看到主机发完27个下降沿，都不等于STC执行确认。无应答/坏帧应按不确定结果处理：STOP超时可能是已执行但应答丢失，不能据此继续退出或升级。

### 收发交接与时序

```text
正常心跳
  -> 主机暂停心跳，释放至少20 ms
  -> 主机前导（下降沿间隔400/32 ms）+ 3字节请求
  -> 主机释放线路并切换为下降沿事件输入
  -> STC READY：最多250 ms内由主循环poll取帧
  -> STC EXECUTING：独立100 ms内执行并准备reply
  -> STC再等100 ms，发同样前导 + 5字节应答，随后释放
  -> 主机核验完整应答，等100 ms后恢复心跳
  -> 留400 ms正常心跳窗口，再允许下一笔事务
```

请求27个下降沿（3个前导沿+24个位沿），应答43个下降沿（3+40）；SYNC沿只用于同步，从下一沿开始解码第一个数据位。每个沿后拉低再释放，**位值由下降沿间隔决定，不由低脉宽决定**。发生超时或I/O错误时，主机仍保留可能的应答窗口，不能立即重新发心跳与STC应答重叠。

| 时序 | 配置与约束 |
|---|---|
| 普通心跳 | 主机每100 ms翻转，下降沿约200 ms；STC有效间隔170–250 ms |
| 前导 | 主机帧前释放至少20 ms；三个下降沿间隔400 ms、32 ms |
| 位0/1 | 下降沿间隔8/14 ms，接收容差±2 ms |
| 低脉宽 | 主机请求2 ms；本版STC应答4 ms，最短位间隔仍留4 ms高电平 |
| READY交接 | 完整请求最多等主循环250 ms，超时丢弃 |
| EXECUTING | poll后独立100 ms准备应答期限，不继承READY的剩余时间 |
| TX等待 | reply准备好后再等100 ms，供主机切为输入 |
| 帧内过期 | SYNC等下一沿最多35 ms；数据等下一沿最多17 ms |
| 空闲过期 | 1秒未见下降沿，忘记旧沿，避免16位时间回绕复用陈旧沿 |
| 主机边界 | 接收上限1700 ms、整笔2600 ms；有效帧后等100 ms再恢复心跳，之后留400 ms正常心跳窗口 |

READY预算：最长状态日志按140字符上界，加一次释放日志18字符，9600/8N1下线上发送约165 ms；还须计入计算和中断耗时。增字段、降波特率或加阻塞调用时必须重新验证250 ms预算，不可取消超时。请求末沿到应答最后释放的保守配置上界为250+100+100+400+32+40×14+4=1446 ms，另加实际时基/执行误差；主机1700 ms接收窗口不变。

应答4 ms只增加旧Tina GPIO中断线程回读电平的采集余量，**不保证任何负载下绝不漏采**。若中断线程晚于低脉冲结束，仍可能漏沿；线程采样时间戳抖动也仍受±2 ms解码容差约束。必须做高负载与示波器验收，不改SDK来绕过本轮边界。

INT2分类输入边沿；Timer0计时、处理过期并发应答；CRC、命令执行和reply在主循环完成。poll/reply须关总中断。Timer0/INT2保持同一默认优先级、互不嵌套；静态检查禁止引入优先级寄存器写操作。应答GPIO辅助函数只由Timer0调用，不跨ISR/主循环共享C51局部变量调用链。

为区分帧首沿，后一个普通下降沿确认前一心跳时刻，日志年龄含确认延迟。通信期间普通心跳暂停，事务中约1至2秒年龄增长可能正常。序号仅区分有限事务窗口，不用于跨重启防重放；一个5字节收发复用缓冲区，无队列或重复应答缓存。

## 版本配对

本版保留原3/5帧、CRC、位间隔和状态编码，与已验证的Linux开漏短帧基线兼容（本产品APP提交 `e711f7c4`）。先只更换STC，不要求因本轮改动重编APP或重打IMG。STC本地C接口更名不影响线协议；重复复位是本版新增行为。

Linux模块已加入纳秒发送期限、可选实时优先级及业务feed接口；大堂机产品层进一步启用业务feed、启动前移和后台START守护，当前新增产品策略尚待实板验收。STC自身不感知哪个业务线程feed，只判断普通心跳。两份冻结分别记录STC与Linux源码版本，接口兼容不等于新配对已经完成量产验收。

## 编译与烧录

1. Keil打开 `RVMDK/STC8G1K08-RESET.uvproj`。正式工程只引用目录内五个源码和User/Driver头文件；标准STARTUP.A51、C51库由工具链提供。
2. 保持SMALL，执行Rebuild，要求零错误、零警告。不得加LARGE、XDATA/IDATA迁移或屏蔽overlay警告绕容量问题。
3. 使用同次 `RVMDK/list/stc8g1k08_reset.hex`、M51及构建日志；list由Keil生成，不放入干净源码交付。归档旧HEX不代表本版源码。
4. 旧v1.1.0基线 `data=112.0 xdata=0 code=4283` 不是本版结果。新增参数、函数和改名均可能改变C51布局及overlay，不能用GCC模拟结果推断Keil容量。
5. 检查M51的DATA/IDATA布局、调用链、overlay和栈；CODE不得超出工程IROM 0x0000..0x1FF8。DATA=112不能直接推出栈只剩16字节。

详见 [烧录说明](docs/flashing.md) 和 [验证记录](docs/verification.md)。保留旧已验证HEX供测试板恢复，先验证新源码构建，再烧录新HEX；不要只根据横幅版本或旧日志放行量产。

## 移植与交付

优先复用 `heartbeat_monitor` 和 `reset_controller`；`main.c`、Config、寄存器头、UART及链路GPIO/时基按新平台适配。保留32位毫秒判断、16位短帧计时、临界区及同级不嵌套中断约束，更换MCU不承诺零修改。

保持五模块、单实例、一个收发复用缓冲区及SMALL/DATA决策路径；不加动态分配、回调表、消息队列或跨工程共享框架。复位状态机复用一个时间戳分别记录ASSERT与WAIT_RECOVERY起点，不新增全局恢复计时字段。

对外复制整个本目录，排除生成的 `RVMDK/list/`、构建目录和个人IDE状态，不发archive或整个STC工作仓库。若交付可烧录产物，另附同次HEX、M51、工具版本、源码版本和SHA-256，不带许可证或个人IDE信息。
