# STC8G1K08 外部看门狗 v2.0.0

独立 Keil C51 工程：`RVMDK/STC8G1K08-RESET.uvproj`。只交付本目录，不引用 Linux 源码。必须配套 v2.0 主机；不与 v1.x 混刷，保留原配对版本用于回退。本版已用 Keil C51 构建（DATA=103.0、XDATA=0、CODE=4457，零错误、零警告）；同次构建的 HEX/M51 在 `RVMDK/list/`。V853 已完成基础通信和主机失联复位验证；其他主机移植后需独立验收。

## 硬件与职责

- `User/main.c` 初始化板级 GPIO、中断及内部 WDT，在主循环执行命令并控制 P5.5。24 MHz 配置对应现有 Timer0 1 ms 刻度；不是要求主机达到 1 ms 精度。
- `Driver/src/cpu_check_link.c` 独占 P5.4，开漏拉低/高阻释放，需要外部上拉；INT2 对输入下降沿分类，Timer0 递减等待并发送应答。收发复用 3 字节，无动态分配。poll/reply 在短临界区交接。
- `heartbeat_monitor.c`、`reset_controller.c` 独立判断心跳与控制复位状态；`uart.c` 仅诊断。不在定时 ISR 打印、算 CRC、执行命令。
- 冷上电/低压默认停止，单独内部 WDT 复位仍恢复监测。P5.5 正常低、复位高约 200 ms；真实失联 5 秒，首次 START 宽限 30 秒，复位释放后给 120 秒恢复窗口，仍未恢复则重试。STOP 不关闭内部 WDT。主机启动原因不采集；复位动作及串口诊断仍保留。

## 唯一协议：v2.0 主机移植与线上时序

以下说明用于给另一款主机实现 `START / STOP / READ`，不需要引用 V853 源码。线上只有一根半双工 `CPU_CHECK` 通信线（STC P5.4）。主机发起请求，STC 才发送应答；同一时刻最多一笔事务。主机 GPIO 只需三种操作：**主动拉低、释放为高阻、在线路释放时记录下降沿时间戳**。空闲时由外部上拉为高，任何一方都不得推挽输出高。不要操作独立的 P5.5 复位输出，也不要把 UART 诊断口当成协议口。

### 1. 用什么量时间：从下降沿量到下一下降沿

每个协议脉冲都先拉低标称 20 ms，再释放。信息编码在**相邻下降沿间隔**，不在低电平宽度；请求和应答方向完全相同。下表低/高两列是发送目标，接收窗是对整个下降沿间隔的判定（含端点）。

| 符号 | 拉低 | 随后释放为高 | 标称下降沿间隔 | 接收窗 | 10 ms/tick 主机：低＋高 |
|---|---:|---:|---:|---:|---:|
| 前导 BREAK | 20 ms | 110 ms | 130 ms | 120–140 ms | 2＋11 tick |
| 同步 SYNC | 20 ms | 80 ms | 100 ms | 90–110 ms | 2＋8 tick |
| 数据位 0 | 20 ms | 20 ms | 40 ms | 30–50 ms | 2＋2 tick |
| 数据位 1 | 20 ms | 50 ms | 70 ms | 60–80 ms | 2＋5 tick |
| 普通心跳（不是协议脉冲） | 100 ms | 100 ms | 200 ms | 170–250 ms（STC 空闲态） | 10＋10 tick |

例如，在数据段量到 55 ms 既不是 0 也不是 1，应丢弃该帧、重新找前导。不要把 ±10 ms 当作缩短标称 20 ms 脉冲的许可。也不要套用旧版的 8/14 ms 或 4 ms 应答。

### 2. 帧如何开始、如何数满 27 个下降沿

1. 正常运行时主机每 100 ms 翻转一次。STC 用**后一个**普通下降沿确认**前一个**心跳。发请求前先建立连续的正常心跳间隔，不要在任意一次翻转处截断心跳硬插入请求。
2. 将请求第 1 沿排在**原本下一次普通下降沿**的位置。例如，前两次普通下降沿为 `−400、−200 ms`；在 `−20 ms` 保持线路释放（不产生沿），`0 ms` 拉低产生第 1 沿。这一沿恰好确认 `−200 ms` 的心跳。随后 `20 ms` 释放、`130 ms` 拉低产生第 2 沿，STC 识别 BREAK；`150 ms` 释放、`230 ms` 拉低产生第 3 沿，STC 识别 SYNC。**第 3 沿还没有传完任何数据位。**
3. 从第 3 沿开始，每个数据位按表发送一个间隔，字节顺序不变、每字节 bit7 先发。第 3→4 沿表示第一个数据位，第 26→27 沿表示最后一个数据位。因此一帧是 `1 个起点＋2 个前导/同步间隔＋24 个数据间隔＝27 个下降沿`。第 27 沿仍保持低 20 ms 才释放，**不再产生第 28 沿**。

发送器伪代码（请求、应答通用，从本方向第 1 沿起算；`wait_until` 使用同一单调时钟的绝对时刻）：

```text
t = 预定第1沿时刻
for interval in [130, 100] + 按 MSB 顺序把 24 位映射为 40 或 70:
    wait_until(t);      拉低
    wait_until(t + 20); 释放
    t = t + interval
wait_until(t);      拉低       # 第27沿，接收方在这里判出最后一位
wait_until(t + 20); 释放       # 帧结束，交出线路
```

伪代码描述标称波形。实现时要计入线程唤醒和 GPIO 写入耗时：不要因上一段迟到而把下一段高/低压短到 20 ms 以下。V853 若比标称发送期限迟到 **≥10 ms**，停止继续发送，释放并转入可能的应答窗口，而不是追赶或立即重发。

### 3. 帧内容与主机确认条件

| 字节 | 请求（主机 → STC） | 应答（STC → 主机） |
|---|---|---|
| 0 | `01` START、`02` STOP、`03` READ | bit7..6 回显命令；bit5 为拒绝标志（0=执行成功）；bit4..2 为阶段；bit1 为本轮见过心跳；bit0 为已启用 |
| 1 | 非零序号 1–255；用完从 1 继续 | 原样回显请求序号 |
| 2 | 对前两字节求 CRC-8 | 对应答自己的前两字节求 CRC-8 |

CRC 参数：多项式 `0x07`，初值 `0x00`，不反射，末尾不异或；每字节先异或入 CRC，再从最高位起左移 8 次，原最高位为 1 时异或 `0x07`，始终保留低 8 位。阶段值：0=停止，1=启动宽限，2=监测，3=正在断言复位，4=等待主机恢复。`heartbeat_seen=1` 表示本轮见过心跳，不保证此刻健康。

主机只接受 CRC 正确、命令与非零序号均匹配、阶段与启用位一致的应答（停止对应阶段 0，启用对应阶段 1–4）。拒绝不能记为成功；成功的 START 还须 `enabled=1`，成功的 STOP 须 `enabled=0`。已启用时重复 START 不重开宽限，READ 不刷新心跳。STC 对未知命令、序号 0、CRC 错误的请求直接丢弃，不发拒绝帧。

### 4. 完整 READ 对照波形（逻辑分析仪验收用）

取 `READ seq=08`，假设当前已启用、在监测阶段且见过心跳。线上应为 **`03 08 07 → CB 08 42`**。请求首字节 `03 = 00000011` 对应 SYNC 之后的八个间隔 `40,40,40,40,40,40,70,70 ms`。下表两列**分别以各自第 1 个下降沿为 0**，不把 MCU 处理/换向时间加到应答列。

| 定位点 | 请求 `03 08 07` | 应答 `CB 08 42` |
|---|---:|---:|
| 第 1、2、3 沿：起点、前导结束、同步结束 | 0、130、230 ms | 0、130、230 ms |
| 第 11 沿：第 1 字节收完 | 610 ms | 700 ms |
| 第 19 沿：第 2 字节收完 | 960 ms | 1050 ms |
| 第 27 沿：CRC 收完 | 1370 ms | 1430 ms |
| 最后低脉冲释放 | **1390 ms** | **1450 ms** |

这不是固定帧长：24 个数据位中每多一个 1，帧长增加 30 ms。其他序号或状态的 CRC 也会变，不能按上例的结束时刻切断收发。

### 5. 换向、超时与恢复心跳

| 从哪里开始计时 | 谁做什么 | 期限或动作 |
|---|---|---|
| STC 收到请求第 27 沿 | 完整请求交给主循环；主机完成尾部低 20 ms 后释放并监听 | STC 最多等待取帧 **250 ms**，逾期丢弃 |
| STC 主循环取走合法请求 | 执行命令、取样状态、准备应答 | 新的 **100 ms** 执行期限，不继承上一阶段剩余时间；逾期不再发该笔应答 |
| STC 应答准备好 | 线路保持释放，给主机切输入的时间 | 再等标称 **100 ms** 才发应答第 1 沿。250/100 ms 是取帧/执行上限，不是固定要等满的延时 |
| 主机切入接收 | 按第 1–27 沿解码，检查命令、序号、CRC、状态 | V853 接收上限 **2500 ms**；另从本笔发送准备开始计 **4200 ms** 整笔上限，先到者生效，不相加 |
| 主机认出有效应答 | 继续释放线路，不抢 STC 的尾脉冲 | V853 从认出应答再等 **100 ms** 才结束事务 |
| 事务结束 | 在业务 feed 有效时恢复普通心跳 | V853 约 **100 ms** 后开始翻转；前 **500 ms** 留给普通心跳，不发下一笔命令。这不是再静默 500 ms |

收到半帧、丢沿、坏应答或发送迟到，不得立刻用心跳/重发覆盖对方可能正在发送的应答。保持释放到接收期限，再恢复普通心跳，按新事务查询或重试。**没收到应答只表示结果未知**：尤其不能把 STOP 超时当作已经停狗并进入升级重启。有维护 STOP 待发时，先让在途帧收尾，再让 STOP 优先于新的状态巡检。

### 6. 移植完成后如何判断能否接入

- **使用 10 ms 调度节拍的主机**：按第 1 节的 tick 数发送即可，不要求主机实现 1 ms 定时器。接收优先用带时间戳的下降沿通知；若用 10 ms 轮询，要在真实业务负载下量**实际最长采样间隙**，确认不会漏过最短的低/高电平，并用第 4 节核对解码间隔。名义轮询周期不等于最坏调度延迟。
- **不要让引脚线程替业务喂狗**：例如 V853 在业务主循环结束时续期（约每秒一次），独立线程仅在续期有效时输出普通心跳；约 10 秒没有业务续期就停止心跳。STC 在已进入监测后，以最后一次已确认的普通心跳为准，失联约 5 秒复位主机。协议沿、CRC 正确的 READ、MCU 自己的应答都不能续命。
- **先对波形，再判可靠性**：抓一笔请求和应答，各数满 27 沿；核对低脉宽、各间隔、换向与心跳恢复。再验证 START/STOP/READ、重复 START、真实业务负载及丢应答重试。健康业务的最大有效心跳年龄验收目标 **≤4800 ms**，不要为兼容慢主机放宽 5 秒保护。按“后沿确认前沿”从波形计算；每秒串口 `age_ms` 会漏峰值，不能代替波形测量。
